# Contributing to CloudZero projects

Welcome, and thank you for considering a contribution to CloudZero open source
projects. People like you make these projects work for the community.

Reading and following these guidelines helps everyone use time well. It also
means you agree to respect the time of the people who maintain these projects.
In return, we will assess your issue or change and help you finish pull
requests.

## Code of Conduct

We take our open source community seriously and hold ourselves and other
contributors to high standards of communication. By participating, you agree to
uphold our [Code of Conduct](CODE-OF-CONDUCT.md).

## Getting Started

Contributions happen through Issues and Pull Requests (PRs). A few guidelines
that cover both:

- To report security vulnerabilities, follow [SECURITY.md](SECURITY.md). Do
  not file a public issue.
- Search for existing Issues and PRs before creating your own.
- We try to handle issues quickly, but impact and root-cause work can take
  time. A polite ping in the comment thread can help if you are blocked.
- Be kind and professional. Avoid assumptions; oversights happen.

### Issues

Use Issues to report problems, request a feature, or discuss a change before
you open a PR. The issue form asks for the details we need to investigate.

If an existing Issue already covers the problem, add your reproduction notes
there instead of opening a duplicate. Adding a
[reaction](https://github.blog/news-insights/product-news/add-reactions-to-pull-requests-issues-and-comments/)
also shows maintainers that more than one person is affected.

### Pull Requests

PRs are welcome and are often the fastest way to get a fix or improvement into
the next release. In general, PRs should:

- Only fix or add the functionality in question **or** address widespread
  whitespace/style issues, not both
- Add unit or integration tests for fixed or changed behavior when a test
  suite exists
- Address a single concern in as few changed lines as possible
- Include documentation in the repo or on our
  [docs site](https://docs.cloudzero.com/)
- Complete the Pull Request template that loads when you open the PR

For changes that touch core behavior or need a breaking (major) release, open
an Issue first. That is optional, but it often saves review time.

We follow the
["fork-and-pull" Git workflow](https://github.com/susam/gitpr):

1. Fork the repository to your own GitHub account
2. Clone the project to your machine
3. Create a branch with a short, descriptive name
4. Commit changes to the branch
5. Follow any formatting and testing guidelines for this repo
6. Push changes to your fork
7. Open a PR and fill in the PR template so we can review efficiently

## Getting Help
